# Ошибки словного поиска на dev

Проверены только 1 500 запросов dev, `qid` от 3000 до 4499. Разметка audit и ответы benchmark не использовались. Источники: `lexical_heuristic_dev.json`, `lexical_heuristic_dev.queries.parquet`, соответствующая часть `features_lexical.parquet` и метаданные нужных объявлений.

## Где теряется качество

Текущий `lexical_heuristic` даёт **Recall@50 = 0,858833**, а объединение всех источников — **0,966778**. В среднем на запрос приходится 545 кандидатов. Основной резерв сейчас находится в отборе уже найденных объявлений: 10,79 процентного пункта против 3,32 пункта потерь при генерации.

| Результат для положительной пары | Число пар |
| --- | ---: |
| Объявление попало в первые 50 | 1 376 |
| Объявление найдено, но стоит ниже 50 | 177 |
| Объявление отсутствует в объединении | 53 |

Всего проверены 1 606 положительных пар. Неполная генерация затрагивает 52 запроса, ошибки отбора — 169, хотя бы один пропуск в ответе — 219. Числа по парам не следует выдавать за macro Recall: запросы с несколькими ответами имеют другой вес.

Среди 53 пропусков генерации в 26 случаях запрос не имеет ни одного общего стем-токена с заголовком, полным описанием и параметрами правильного объявления. В 40 случаях покрыто не больше половины токенов. Отбором из существующего объединения эти ошибки исправить нельзя. Семантический поиск здесь имеет понятную цель, но его фактический выигрыш ещё нужно измерить.

У пропусков генерации пустые фильтры встречаются в 66,0% случаев, точное совпадение локации — в 49,1%. Для найденных в первых 50 положительных пар соответствующие доли составляют 44,5% и 79,9%. Разница идентификаторов не всегда означает большое расстояние: локация запроса может обозначать регион.

## Какие источники нужны

Географический BM25 нашёл 1 485 из 1 606 положительных пар, включая **41 пару, отсутствующую во всех остальных источниках**. Поиск по запросу вместе с фильтром дал 30 таких уникальных пар, географический символьный канал — 8. Глобальный BM25 добавил 2, глобальный символьный поиск — 1. Глобальный словный канал не добавил уникальных положительных пар в этой проверке.

Поведенческие каналы нашли 20 положительных пар, но все они уже встречались в других источниках. Делать вывод о бесполезности памяти рано: только 3,24% целевых объявлений dev сохранили обучающую историю. Проверка специально смещена к новым объявлениям.

Для всех 53 потерянных пар дополнительно измерены точные позиции в существующих словных индексах. При текущих лимитах повторный расчёт не возвращает ни одну из них, что совпадает с сохранёнными признаками.

| Изменение лимитов | Дополнительно найденные положительные пары |
| --- | ---: |
| Все словные лимиты ×2 | 15 из 53 |
| Все словные лимиты ×4 | 21 из 53 |
| Все словные лимиты ×8 | 28 из 53 |
| Только географический BM25: 220 → 440 | 6 из 53 |
| Только географический BM25: 220 → 880 | 14 из 53 |
| Только географический символьный: 220 → 440 | 5 из 53 |
| Только запрос с фильтром: 120 → 240 | 4 из 53 |

Увеличение глобальных словного и символьного каналов со 100 до 400 кандидатов не вернуло ни одной потерянной пары. Указанные прибавки относятся только к попаданию в объединение. Они не обещают такой же прибавки к Recall@50 после отбора, а результаты отдельных каналов могут пересекаться.

## Небольшие примеры

| Запрос | Выбранное пользователем объявление | Что произошло |
| --- | --- | --- |
| «вынос холодильника» | «Вывоз старой бытовой техники» | Пропуск генерации, разные формулировки без общего стем-токена в доступных текстах |
| «ремонт соллерс атлант» | «Отключение SCR - DPF Sollers CM2620» | Пропуск генерации, кириллическое название марки и более узкая услуга в объявлении |
| «масьер на час» | «Строительные работы» | Пропуск генерации, опечатка и слишком общий заголовок |
| «установить винду» | «Установка Windows на SSD с переносом данных» | Объявление есть в объединении, но исходная оценка ставит его на 466-е место |
| «перепахать участок» | «Расчистка,выравнивание,фрезеровка,подъем целины» | Объявление есть в объединении через фильтр, но стоит на 554-м месте |

Некоторые положительные пары слабо объясняются доступным текстом. Отдельный выбор пользователя может быть нетипичным, а содержимое объявления могло измениться. Для таких случаев нельзя обещать устранение ошибки одной понятной эвристикой и подгонять словарь под конкретные проверочные запросы.

## Что проверять дальше

1. **Сначала улучшить отбор существующего объединения.** В нём уже есть 177 пропущенных положительных пар. Обучаемый отбор должен учитывать оценки каналов, их позиции, контекст, категории и географию совместно. Сравнивать его нужно по Recall@50 всех запросов, включая пропуски генерации.

2. **Добавить смысловой канал и измерить его уникальный вклад.** Половина пропусков генерации имеет нулевое словное пересечение. Приоритетны синонимы, разговорные формулировки, написание марок на разных языках и объявления с общим заголовком. Нужны глобальные и географические кандидаты E5, затем проверка дополнительного покрытия на том же dev.

3. **Использовать фильтры и распределение подкатегорий при отборе.** Среди 177 ошибок отбора у 90 положительных пар вероятность подкатегории по похожим запросам не ниже 0,5, у 47 вероятность подкатегории по фильтру не ниже 0,5. Простые диагностические добавки к текущей оценке уже повышают dev Recall@50: `+0.5 × relative_context_word × geo_affinity^0.7` даёт 0,871500, `+0.3 × filter_microcat_probability` — 0,870833, `+0.3 × microcat_probability` — 0,872278. Каждая добавка проверялась отдельно. Коэффициенты служат проверкой направления, не окончательным подбором.

4. **Увеличивать лимиты выборочно.** Первые кандидаты на расширение — географический BM25, географический символьный поиск и запрос вместе с фильтром. Проверить умеренное увеличение после добавления E5: часть новых словных кандидатов может уже находиться нейросетью. Массовое расширение всех источников расходует память и усложняет отбор при быстро уменьшающейся отдаче.

5. **Сохранить сильную географию, но учить исключения.** Снижение общего показателя географической поправки с 0,7 до 0,4 ухудшило dev Recall@50 до 0,824389. При этом среди ошибок отбора есть 29 положительных пар дальше 100 км от оценённого центра. Значит, глобальное ослабление штрафа не подходит, а ширину поиска, историю переходов и смысл услуги нужно рассматривать вместе.

6. **Дать модели больше сведений о совпадении с описанием.** Средняя доля совпавших токенов у ошибок отбора равна 0,211 для заголовка и 0,557 для описания. BM25 уже приносит такие объявления, но одной его оценки может не хватать для выбора 50. Стоит сравнить отдельное покрытие запроса описанием и представление E5, в котором длинные параметры не вытесняют содержательное описание. Исправление смешанных латинских и кириллических букв пока не приоритет: пробная замена визуально похожих букв не увеличила покрытие ни у одной из 53 потерянных пар.

Диагностические варианты сравнивались только на dev. Эти результаты помогают выбирать следующие эксперименты, но сами по себе не являются независимой оценкой окончательной модели.
